## Behavior established from source

These are static contracts for the stage-2 characterization pass. Source anchors are relative to the repository root at R0.

| Boundary | Observable contract and source anchors |
| --- | --- |
| Startup and ownership | `main` delegates to `App::start`. The app is named before the log session. Bootstrap constructs storage, loads jobs/CVs/companies, reconciles managed files, sets six context properties and loads the main QML URL. The engine is declared after the exposed graph. Shutdown closes the gate and joins job save, CV import and removal before graph teardown. A normal return plus all three clean joins is required for the completion event. `src/main.cpp:3–6`, `src/app/App.cpp:29–46`, `src/app/AppBootstrap.hpp:54–75`, `src/app/AppBootstrap.cpp:15–58,93–113,149–176`. See F001 for incomplete cursor reads. |
| Job submission and publication | The controller preflights and queues normalized inputs. The checked and prevalidated service entry points have different validation obligations. A missing row is handled before draft validation on update. A successful add appends the application, emits `companyResolved`, sorts the projection, emits `cvUsed` and then `applicationCreated`. An update publishes the model before `companyResolved` and any `cvReplaced`. Both routes emit completion before releasing the active request if completion was not suppressed. Cancellation can suppress completion while a committed model change is still published. The next request can start before the previous gate reservation is released. `src/jobs/JobApplicationValidator.cpp:82–96`, `src/jobs/UpdateJobService.hpp:100–175`, `src/jobs/JobApplicationsController.cpp:432–470,483–525,535–578,602–616`. |
| Workers and admission | Job saves and standalone CV imports each have a serial queue and a single-active facade. Results cross the worker boundary as values. The facade matches the active operation and token. Shutdown suppresses late delivery, requests cooperative cancellation and destroys the worker SQL context before quit/wait. The GUI gate includes queued work and publication. The shared CV mutex serializes persistence. Create/replacement/import recheck cancellation after acquiring it. Metadata-only updates acquire it too and have no second cancellation check there. FIFO within a queue does not establish ordering between workers. `src/common/SerialOperationQueue.hpp:36–55,88–130`, `src/common/SingleActiveWorkerRuntime.cpp:25–68,98–141`, `src/common/SingleActiveWorkerFacade.hpp:193–221`, `src/jobs/AddJobService.cpp:96–115`, `src/jobs/UpdateJobService.cpp:79–100`, `src/cvs/CvImportExecutor.cpp:103–128`. |
| Database and files | The app-local Data directory owns `database.sqlite` and `Resumes`. Each worker creates its own named connection and releases it on its owning thread. The schema is v4. New DBs take the v4 creation path, existing versions 1–3 follow the version steps under a transaction, and newer schemas are rejected. The SQL guard rolls back while active on unwinding. CV identity uses the content hash and case-sensitive original file name. The buffered input feeds the staged file, then flush/close/rename precede commit. Archived exact matches can be restored without another copy. `src/storage/StoragePaths.cpp:25–36`, `src/storage/SqliteDatabase.cpp:9–15,29–67`, `src/storage/SchemaMigrator.cpp:45–135`, `src/storage/SqlTransaction.cpp:19–48`, `src/cvs/CvImportService.cpp:111–164`, `src/cvs/CvManagedFileStore.cpp:133–228,248–333`. |
| Failure compensation and removal | On failed create/update/import, transaction unwinding precedes completed-file compensation, with the CV mutex held. The path and cleanup outcome affect the exact UI message and diagnostic facts. Removal checks cancellation between items and uses a transaction per item. An active linked CV is archived, an eligible unlinked CV can be deleted, and linked archived CVs are skipped on permanent deletion. File retention precedes SQL delete/commit and cleanup follows commit. Recovery visits tombstones, staged files and unreferenced completed files. `src/jobs/AddJobService.cpp:98–166`, `src/jobs/UpdateJobService.cpp:84–166`, `src/cvs/CvImportExecutor.cpp:110–166`, `src/maintenance/DataRemovalService.hpp:50–93`, `src/maintenance/DataRemovalService.cpp:110–218,221–266`, `src/cvs/CvManagedFileStore.cpp:344–391,410–492`. |

Bulk selection derives ordered IDs from the visible proxy. Dashboard exposes metrics and limited recent models, including `appliedDateLabel` for a job date role. Companies persist, contacts are in-memory. In QML five primary pages and Add Job share a stack. Protected navigation, draft correlation and deferred close are part of the shell. `src/common/StableIdSelectionTracker.cpp:88–165`, `src/common/BulkIdSelectionTracker.cpp:34–47,137–172`, `src/dashboard/DashboardController.cpp:107–146,170–175`, `src/app/AppBootstrap.hpp:61–73`, `qml/Main.qml:32–109,165–212,247–260,504–535`. |

The session outlives worker teardown and drains accepted entries on normal close. Preserve local ordering and operation correlation, including the existing diagnostic deviations in FINDINGS.
