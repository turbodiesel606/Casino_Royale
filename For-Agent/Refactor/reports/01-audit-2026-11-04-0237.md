## Strengths to preserve and priorities

1. **Keep explicit owners.** Bootstrap's member order gives the engine, controllers, worker-local SQL connections, gate, CV mutex and logger a defined teardown relationship. The queue's active/waiting distinction and operation/token correlation are meaningful. The main thread publishes values after persistence. A unified generic worker/service would obscure the differences between create, update, import and removal.
2. **Keep storage boundaries.** Schema-version steps preserve their historical transformations. The managed path resolver, file opener, stage/compensation logic and repository are separate for a reason. Typed SQL values and fixed-string expressions in `CvRepository` must keep their existing call paths.
3. **Reuse only where meaning matches.** Company-only search reset, duplicate traversals of the same concrete source model, two identical icon definitions and three copies of the same drag algorithm have demonstrably identical contracts. The common bulk tracker's domain includes are unnecessary. The two private template implementations can move without changing their compile-time types.
4. **Order by confidence and payoff.** Start with R001–R003 to remove dependencies without modifying active workflows. R004/R005 are independently verifiable local simplifications. R006 crosses a notification and admission boundary. R007/R008 need stage-2 visual references. R009 is last and conditional because cleanup success, failure and rollback need independent evidence. ## Decisions outside the plan

| Investigated transformation | Decision and reason |
| --- | --- |
| Merge add/update/import into a transactional runner | Reject. Metadata-only update takes the shared mutex but skips the second cancellation check under it. Add/replacement/import have different validation and cancellation boundaries. Only the completed-file cleanup/message unit qualifies as R009. `src/jobs/AddJobService.cpp:96–115`, `src/jobs/UpdateJobService.cpp:79–100`, `src/cvs/CvImportExecutor.cpp:103–149`. |
| Unify removal transactions, shorten the lock, or enforce worker fairness | Reject. Best-effort removal commits per item and can continue after failures. The lock spans rollback and file compensation in job/import paths, and the GUI gate outlives each result publication. No fairness contract authorizes a new ordering. `src/maintenance/DataRemovalService.hpp:50–93`, `src/jobs/JobApplicationsController.cpp:602–616`, `src/cvs/CvLibraryController.cpp:862–882`. |
| Drop the typed executor pointer from the facade | Defer. The runtime and facade both refer to the same executor, but changing creation/cleanup callbacks or the type of the queued capture crosses an ownership boundary. No measured or functional need offsets that risk in this plan. A failed post has pre-existing conditional behavior (S001). `src/common/SingleActiveWorkerFacade.hpp:95–107,123–128,193–221`, `src/common/SingleActiveWorkerRuntime.cpp:115–141,149–183`. |
| Share migration normalization with live company logic or rebuild model proxies into one base | Reject. Frozen migration semantics must remain reproducible. Relation filtering, case-folded multi-token search, typed limited sorting and tie breaks have different guarantees. Dashboard stats and funnel also differ in labels/empty ratios. `src/storage/SchemaMigrationV2ToV3.cpp`, `src/common/RoleFilterProxyModel.cpp:91–159`, `src/common/LimitedSortedProxyModel.cpp:183–232`, `src/dashboard/DashboardController.cpp:20–35,83–103`. |
| Remove dormant QML or old common string headers | No deletion. The two `src/common/Header.hpp` and `src/common/FixedStringQt.hpp` files are absent from source registration. Only the latter includes the former. There is no application include of that pair. They are not the active protected library. Registration/call counts alone do not establish removal authority or external consumption. Preserve current registered prototypes and the library caller. |
| Extract protected navigation, draft state or all form fields into C++ | Reject. Transient edits, focus, pending UI actions and notification queues belong to the shell/editor. A shared CRUD screen or new generic form engine would couple distinct page transitions and public contracts. A functional Settings route, real pagination, dynamic contact filter choices or format-sensitive icons would change behavior. `qml/Main.qml:47–109,141–212,247–260`, `qml/pages/JobDescriptionPane.qml:181–238`, `qml/pages/JobsApplicationsPane.qml:336–351`, `qml/pages/ContactsPage.qml:74–76`. |
| Repair findings, redesign logging or reorganize targets/installers | Outside the authorized refactor. Preserve logging event text, counts, severity/ordering and best-effort failures, including pre-existing deviations. Only the two additive QML file registrations are anticipated for R007/R008. No packaging, installer, new dependency, schema migration or settings change. |
