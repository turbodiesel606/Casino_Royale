script and reviewed 148-file payload inventory. It consumes the existing
generated Release identity, checks the current project version and production

generated build metadata or test helper is included. CMake's built-in 7zip
writer avoids a separate archive tool dependency. This format matches
[Inno Setup's native archive extraction support](https://jrsoftware.org/ishelp/topic_setup_archiveextraction.htm);
[CMake documents 7zip, file lists and timestamp control](https://cmake.org/cmake/help/v3.21/manual/cmake.1.html#run-a-command-line-tool).
Actual Inno compilation/extraction remains a later-stage check.

Two independent runs produced byte-identical archives, checksum sidecars and
JSON manifests, using ordinal paths and normalized snapshot timestamps. Archive
creation verifies the exact extracted file list and each file's size/SHA-256
before writing the final manifest. Verify mode requires an expected version and
fails on missing/mismatched identity, assets, checksum sidecar or extracted data.

## Remaining blockers and risks

No essential stage-06 blocker remains. These are intermediate release payloads,
not an approved public release. MSVC deployment is still stage 09 work. The
host's system runtime can mask missing-runtime behavior. Missing DXC/graphics,
GUI, clean-machine and licensing acceptance from earlier stages remain open.

Reproducibility is for identical staged bytes and the same CMake/libarchive
implementation (here CMake 4.0.2), not for independently compiled binaries or
across compression-tool versions. The archive uses fixed timestamps; no claim
of deterministic compiler output or debug-information sanitization is made.

The exact inventory blocks unrecognized files; it does not prove arbitrary
contents in an approved filename are trustworthy. Use trusted inputs and audit
the shipped set. Verification trusts the local manifest; it is neither signed
metadata nor a hostile archive sandbox. Stage 08 must embed the verified hash
and version as trusted installer build inputs, never trust a downloaded manifest
as its own authentication. Future runtime/license additions need deliberate
inventory/path-policy updates and new archives/checksums.

Manual acceptance must later run the chosen Inno extraction path and full GUI
on clean Windows 10/11 x64 machines. Use a disposable account/VM: the unchanged
SQLite/CV data identity may be shared by two installations in the same account.
