### Mixed-version SQLite evaluation

Live `App.cpp`/`StoragePaths.cpp` retain the shared account storage identity:
`QStandardPaths::AppLocalDataLocation` already includes application name
`JobTracker`; `StoragePaths` adds `Data/database.sqlite` and `Data/Resumes`. On Windows
the resulting normal account location is `%LOCALAPPDATA%/JobTracker/Data`.
Separate installation records do not give separate data stores.

`SchemaMigrator.cpp` supports schema 4, rejects newer schemas, applies supported
forward steps transactionally, and checks foreign keys. The executed migration
suite verifies initialization/reopen, upgrades from 1/2/3, blank-company rollback,
newer-schema rejection and connection cleanup. Raw results are retained in
`dist/stage13-evidence/migration-tests.txt`.

Installer equality checks prevent registered mixed-version coexistence and fail
closed on untrusted/unavailable profiles. This does not prove compatibility of
unregistered copies or distinct binaries reusing a version string, nor does
SQLite transactional behavior prove multi-process CV filesystem safety. These
remain explicit acceptance limits; no storage or application logic was changed.
